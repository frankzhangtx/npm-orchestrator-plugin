// TextParsingSupport.kt：当前真实代码片段
private val knownCities = listOf(
    "上海", "北京", "深圳", "杭州", "成都",
    "南京", "武汉", "苏州", "厦门", "广州"
)

// 阅读说明：名单中没有“重庆”，因此不会命中。
fun extractCity(text: String): String? {
    return knownCities.firstOrNull { text.contains(it) }
}
// RuleBasedIntentParser.kt：列表分支已经读取 city
when {
    looksLikeList(input) -> ParseResult(
        userGoal = UserGoal.BrowsePersonalInfoList,
        slots = ParseSlots(
            listPosition = extractPosition(input),
            personName = extractLookupName(input),
            phone = extractPhone(input),
            city = extractCity(input)
        ),
        confidence = 0.88f,
        parserMetadata = buildMetadata(startedAt)
    )
}

手工触发 Coder，而不是创建定时 Job

下面只是手动运行与未来 Scheduler 相同的 Agent 和固定 Prompt。 不得添加 --dangerously-skip-permissions。

  "$(<automation/scheduler/coder-prompt.txt)"

Coder 会自行选择唯一的 PENDING 任务、执行 G0、记录真实 RED、做最小实现并调用 quality-gate.sh。成功后状态只能由脚本变为 READY_FOR_REVIEW。

H1 人工验收、提交与选择性合入

人工检查最终 diff、RED/Gate/Review 证据和任务验收条件。通过后才提交两个允许路径中的产品修改。 专用分支包含本机激活配置时，应只选择性带回产品提交，避免把绝对 worktree 路径合入主分支。

Acceptance

最终人工验收清单

07

业务行为

  • 查看重庆的记录列表 返回成功解析结果。
  • userGoal == BrowsePersonalInfoList。
  • slots.city == "重庆"。
  • 上海等已有城市行为保持不变。
  • 没有顺带增加区县、别名或模糊匹配。

测试与构建

  • 能看到实现前的真实 RED 日志。
  • 聚焦测试与全量 JVM 单测通过。
  • Debug APK 构建通过。
  • Android Lint 通过。
  • 设备测试按合同明确标记为不需要。

范围与权限

  • 产品 diff 只落在合同允许路径。
  • 没有修改 Agent、Skill、任务合同或门禁脚本。
  • 没有删除、忽略或弱化测试。
  • Coder 没有 push、merge、rebase 或创建 worktree。
  • Reviewer 全程没有编辑仓库文件。

状态与证据

  • ready.json 记录基线 HEAD 与 diff SHA。
  • review.json.decision == APPROVED。
  • verificationExitCode == 0。
  • 最终状态是 AWAITING_HUMAN。
  • 产品 diff 在 Reviewer 完成前没有被提交或改变。

Stop Conditions

常见误区与失败处理

V1 的价值不只在于“能完成”，更在于条件不满足时能确定地停下。

08
不要

预建合同再输入任务

正确顺序是先向 Planner 输入自然语言，审批后由 Planner 生成文件。

不要

在脏主工作区运行 Coder

claim-task.sh 会阻断；任务必须在已配置、干净的专用 worktree 中执行。

不要

跳过权限

--dangerously-skip-permissions 会绕开方案的重要安全边界，禁止使用。

遇到失败

保留状态与日志

BLOCKED、TEST_FAILED、CHANGES_REQUESTED 都不能自动重试。

重新排队

必须再次人工批准

先解决环境、合同或代码问题，再显式执行 queue-task.sh。

最终边界

只到 AWAITING_HUMAN

V1 不自动提交、push 或 merge；最终风险接受始终属于人类。
