# OpenCode Android Orchestrator 0.6.0 Release Notes

Status: published to the public npm Registry on 2026-09-01.

## Highlights

- Makes automatic Android verification-task discovery reliable when the target
  repository enables Gradle Configuration Cache.
- Passes `--no-configuration-cache` only to the temporary, configuration-only
  `gradlew help` discovery invocation. The target project's
  `gradle.properties` and normal build behavior remain unchanged.
- Prevents a reused configuration from skipping the discovery init script's
  `projectsEvaluated` callback and producing a false empty verification matrix.
- Adds regression coverage for the exact Gradle discovery arguments and two
  consecutive discovery calls.

## Compatibility

- The certified OpenCode versions remain `1.14.22` and `1.15.13`, with peer
  range `>=1.14.22 <1.16.0`.
- Existing `0.5.0` installations retain their generated verification matrix
  during upgrade unless an explicit reviewed override is supplied.
- No WordPress or other consumer-project Gradle setting needs to be changed.
- TypeScript type checking, 135 Node tests, the audited 42-case Shell lifecycle
  suite, deterministic packing, and clean-consumer checks gated publication.

## Install and upgrade

Initialize a new project with the fixed version:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.6.0 init . --json
```

For a healthy manifest-managed installation, run the fixed version's doctor
before upgrading:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.6.0 doctor . --json
npx @frankzhang2026/opencode-android-orchestrator@0.6.0 upgrade . --json
```
