# 1.3.1 regression follow-up

Date: 2026-10-13. The interrupted full regression has now been completed and all
five failing cases have passed focused follow-up. This is not a claim that the
first complete run was entirely green.

## Source and change

The validation copy initially matched all 212 tracked files at product commit
`1da6c9bb23b663acddc4e8101ccac7da2ed4651a`. TypeScript compilation passed.

Four nested Android build lifecycle fixtures create new unscoped contracts despite
declaring project capabilities. Version 1.3.1 correctly rejects those drafts unless
the full verification scope is explicitly justified. The fixtures now provide
`verificationFallbackReason` and assert that approval text displays it. Their
original contract versions, task sets, lifecycle checks, SDK/build-root checks and
decoy-wrapper protections remain exercised. Production code is unchanged.

## Completed verification

- Full Node regression, serial: **371 tests, 366 passed, 5 failed, 0 cancelled,
  0 skipped**, exit code 1, approximately 38 minutes 53 seconds.
- Four failures were the nested-build fixture incompatibility described above.
  The full run executed those cases before the fixture correction was applied.
- The fifth failure was the Review environment recovery case. Its supervisor
  recorded `Clock moved backwards; retain execution slot` and entered ownership
  protection. A subsequent 45-second clock sample observed no rollback. The test
  passed on follow-up without modifying the supervisor or weakening its checks;
  the original failure remains recorded and is not counted as a first-run pass.
- Focused follow-up: **7/7 passed**, exit code 0, approximately 3 minutes 38 seconds.
  This includes the unchanged Review recovery case, all four corrected nested
  lifecycles, nested installation discovery, and direct Gradle invocation guards.
- No test expectations were relaxed. The full suite was not repeated after this
  test-only correction; all previously failing cases were explicitly rerun.

The initial sandboxed attempt failed on `spawnSync ps EPERM`. The complete serial
run and follow-up used approved execution outside the sandbox because process
identity inspection is necessary for these tests.
