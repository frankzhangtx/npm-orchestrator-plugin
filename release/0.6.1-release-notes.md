# OpenCode Android Orchestrator 0.6.1 Release Notes

Status: published to the public npm Registry on 2026-09-01; post-publication
verification completed on 2026-09-02.

## Highlights

- Gives direct managed long-running lifecycle commands a configurable
  30-minute (`1800000` ms) default timeout without shortening a larger caller
  timeout or changing unrelated commands.
- Adds the bounded `longCommandTimeoutMs` setting and the matching
  `--long-command-timeout-ms` `init` and `upgrade` option. Accepted values are
  `120000` through `7200000` milliseconds, and upgrade preserves an installed
  value.
- Adds `/resume-task` and `resume-task.sh` for one explicitly approved recovery
  when baseline capture was externally interrupted before `baseline.json` was
  sealed.
- Makes baseline recovery fail closed unless refs, HEAD, lease, transition
  history, planning hashes, zero product changes, absent downstream evidence,
  and the one-retry bound all hold.
- Expands the managed inventory from 45 to 47 files, executable automation
  scripts from 28 to 29, and the Shell transaction suite from 42 to 44 cases.

## Compatibility

- The certified OpenCode API versions remain `1.14.22` and `1.15.13`, with
  peer range `>=1.14.22 <1.16.0`.
- Healthy manifest-managed `0.2.0` through `0.6.0` installations can upgrade
  to `0.6.1`; a missing prior timeout receives the 30-minute default.
- Existing module scope, Gradle verification tasks, original-file backups, and
  an explicitly configured valid timeout are preserved during upgrade.
- TypeScript type checking, 138 Node tests, the audited 44-case Shell lifecycle
  suite, deterministic packing, and two-version clean-consumer checks passed.

## Install and upgrade

Initialize a new project with the fixed version:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.6.1 init . --json
```

For a healthy manifest-managed installation, authenticate the current state
with the exact installed version first, run the fixed target version's upgrade,
and then run the target version's doctor. For example, upgrade `0.6.0` with:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.6.0 doctor . --json
npx @frankzhang2026/opencode-android-orchestrator@0.6.1 upgrade . --json
npx @frankzhang2026/opencode-android-orchestrator@0.6.1 doctor . --json
```

The first doctor must match the installed manifest version. Running the target
`0.6.1` doctor before upgrade correctly reports the old `0.6.0` identity,
45-file inventory, templates, plugin reference, and missing timeout field as
different from the `0.6.1` target. That target-version failure is not evidence
that an otherwise healthy older installation is damaged.

Use `/resume-task <TASK-ID>` only after its fresh approval question and only
for the narrow baseline-interruption state described above. It is not a general
retry or a bypass for failed tests, review findings, or product changes.
