# OpenCode Android Orchestrator 0.4.0 Release Notes

Status: release candidate for the public npm Registry on 2026-08-29.

## Highlights

- Adds the human-maintained `.automation-worktree-allowlist` for intentional
  local changes that must stay outside orchestration. Each non-comment line is
  one exact repository-relative file path; directory and pattern bypasses are
  rejected.
- Excludes approved tracked, untracked, and staged local changes consistently
  from startup cleanliness, task scope, diff hashes, acceptance and abort
  evidence, archival, and deterministic task or recovery commits.
- Snapshots the validated list when a contract is approved, exposes the
  effective snapshot in task status for Coder and Reviewer sessions, and keeps
  isolated task worktrees unfiltered so task-local changes cannot be hidden.
- Preserves already-staged allowlisted entries across task and abort commits,
  and treats rename sources and destinations independently so an allowlisted
  destination cannot hide an unlisted source deletion.
- Rejects protected orchestration, Gradle, Git, and planning paths as well as
  duplicate, unsafe, oversized, or symlink-based allowlist input.

## Compatibility and verification

- The plugin remains restricted to APIs shared by certified OpenCode versions
  `1.14.22` and `1.15.13`; the peer range remains
  `>=1.14.22 <1.16.0`.
- TypeScript type checking, 125 Node tests, the audited 42-case Shell lifecycle
  suite, deterministic packing, and clean-consumer checks gate publication.
- The control file is operator-maintained and unmanaged. The installer and
  upgrade transaction install the supporting scripts, agents, skills, and
  policy text but do not create or edit a project's allowlist.

## Upgrade from 0.3.0

Run the fixed `0.4.0` doctor before upgrading:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.4.0 doctor . --json
npx @frankzhang2026/opencode-android-orchestrator@0.4.0 upgrade . --json
```

After a successful upgrade, create `.automation-worktree-allowlist` in the Git
root only when a reviewed local file must remain outside every task. Remove an
entry before starting a task that is expected to modify that file. Existing
`0.3.0` module-scope and verification-task settings remain subject to the
normal guarded upgrade rules.

## Security and recovery

The package still exposes only the read-only
`android_orchestrator_status` and `android_orchestrator_doctor` custom tools.
It does not push Git changes, register background jobs, or bundle Superpowers.
Read [`docs/SECURITY.md`](../docs/SECURITY.md) before enabling model-driven
execution and [`docs/TROUBLESHOOTING.md`](../docs/TROUBLESHOOTING.md) before
manual recovery.

The exact published artifact checksum and Registry round-trip evidence will be
recorded in `release/0.4.0-authorization.md`. npm publication does not imply a
Git tag or GitHub release.
