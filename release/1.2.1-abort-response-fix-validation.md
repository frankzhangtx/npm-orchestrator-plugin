# 1.2.1 abort response defect validation

Date: 2026-10-10. Source baseline: `06ff1525beb195215348a8ac8d76722788766db0`.
Status: unpublished source fix for the already published 1.2.1 package.
Package metadata remains 1.2.1 for local validation; this is not a replacement
of the immutable Registry release. No WordPress installation was upgraded.

## Defect and correction

Interactive task review inlined contracts, plans and complete test inventories
before the registered confirmation question. The reported abort response was
1,284,790 bytes, so host output truncation hid the exact question needed to
obtain a matching one-use approval receipt.

Task-specific status and all four operation reviews now return bounded summaries
and evidence descriptors. The complete registered question appears first in
review output. Serialized UTF-8 responses, including JSON escaping, are limited
to 16 KiB. Full evidence is available through read-only `readEvidence` chunks,
bound to its SHA-256 digest. Cursors also bind task, contract digest, candidate,
target HEAD and resource name. Arbitrary filesystem paths are not accepted.

The approval ledger, actual question-selection requirement, candidate checks,
executor and archive workflow are unchanged. Reading evidence does not replace
a pending question. Global queue status, operator CLI output and persisted
evidence formats retain their previous behavior.

## Verification

- The new large-inventory regression fails against the old task status output
  at 2,149,144 bytes. An earlier fixture typo was corrected before this valid
  reproduction and is not counted as evidence of the product defect.
- Focused presentation and approval tests passed 9/9. They cover all four
  review operations, Unicode and escaped content, stale/mismatched cursors,
  workspace and agent restrictions, exact reconstruction and receipt reuse.
- A real queue worker fixture reaches a failed state, receives a valid approval
  despite oversized evidence, then completes local archival as ABORTED. The
  fixture simulates Gradle/OpenCode responses; its queue, process, Git archive
  and approval ledger execute normally. It exercises the review tool followed
  by ledger consumption and queue request, not an interactive browser click.
- The first full suite passed 329/330 in 760.787 seconds. Its only failure was
  the existing RED/GREEN/Reviewer retry fixture reaching its 90-second timeout.
  The unchanged test passed alone in 44.573 seconds during resumed validation;
  neither implementation nor timeout thresholds were changed for that rerun.
- Final full suite passed 330/330 in 670.545 seconds, with zero failures,
  cancellations or skips (`validation/full-tests-resumed.log`). The previously
  failing retry case also passed within this full run in 81.278 seconds.
- Typecheck and build passed. The 229-file local tarball matches candidate
  contents and modes, includes the new presentation module, and installs into
  an isolated directory. CLI help, packed review and evidence reads passed.

Read-only validation against the retained WordPress task produced 3,692 bytes
instead of 1,284,537 bytes, with an identical confirmation question. Its full
test manifest reconstructed exactly from 63 pages; the largest was 5,322 bytes.
The queue file was byte-identical before and after validation. At that point
the task had already been aborted by the user and was ABORTED; the smaller old
response size reflects this state change from the originally reported failure.

The first focused run encountered sandbox `ps` EPERM, and the first package
attempt encountered npm-cache permissions. Both were rerun successfully with
authorization outside the sandbox; the original logs are retained.
The resumed retry check also encountered `ps` EPERM inside the sandbox, then
passed outside it with authorization. Typecheck passed again on resumption.
All 229 tarball files still match candidate bytes and modes. The previously
smoke-tested installation also matches every file's bytes; npm installation
makes the declared CLI bin executable (0644 to 0755), with all other modes
unchanged.
