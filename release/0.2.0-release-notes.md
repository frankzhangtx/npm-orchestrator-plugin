# OpenCode Android Orchestrator 0.2.0 Release Notes

Status: draft; `0.2.0` is not published.

## Highlights

- Adds a complete `init`, `doctor`, `upgrade`, and `uninstall` lifecycle for
  installing the audited Android orchestration resources into a Git project.
- Supports certified OpenCode versions `1.14.22` and `1.15.13` while limiting
  the plugin implementation to their shared API surface.
- Preserves three fresh human approval questions, single-commit integration,
  repository drift checks, a persistent repository lease, no-push behavior,
  and no Scheduler or launchd registration.
- Treats absent legacy Scheduler tools as disabled in a clean project while
  still requiring explicit deny rules and rejecting enabled tools.
- Adds project-scoped read-only status and doctor tools; mutating custom tools
  remain deliberately excluded from `0.2.0`.
- Adds verified backup manifests, exact hashes and modes, conflict protection,
  rollback evidence, and user-drift preservation across lifecycle operations.

## Compatibility and verification

- TypeScript builds against `@opencode-ai/plugin@1.14.22` with peer range
  `>=1.14.22 <1.16.0`.
- The final local tarball passes clean-project `init`, a zero-write
  same-version `upgrade`, `uninstall` with no retained drift, `re-init`, final
  installed-state doctor, deterministic repacking, and the non-interactive
  discovery/configuration matrix on OpenCode `1.14.22` and `1.15.13`.
- The real-model three-question task closure passed independently on both
  certified versions. Each run produced exactly one combined
  plan/contract/code/test commit, deleted its integrated local task branch, and
  recorded `pushed: false`. The `1.14.22` request also carried all three
  approval labels as untrusted text and still required three fresh UI
  selections.

## Upgrade note for 0.1.0

Published `0.1.0` was an early scaffold without a functional installer. Treat
`0.2.0` as the first usable lifecycle release. Follow
[`docs/MIGRATION.md`](../docs/MIGRATION.md); do not assume the old package has a
manifest-managed installation that can be upgraded in place.

## Security and recovery

Read [`docs/SECURITY.md`](../docs/SECURITY.md) before enabling model-driven
execution and [`docs/TROUBLESHOOTING.md`](../docs/TROUBLESHOOTING.md) before
manual recovery. The package does not push to a remote, does not register
background jobs, and does not bundle Superpowers. License and dependency
attribution are recorded in [`LICENSE`](../LICENSE) and
[`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).

## Release status

Publication remains blocked until every gate in
[`release/0.2.0-authorization.md`](0.2.0-authorization.md) is resolved and the
user explicitly authorizes the exact artifact and external actions.
