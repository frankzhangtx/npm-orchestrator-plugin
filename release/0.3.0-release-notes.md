# OpenCode Android Orchestrator 0.3.0 Release Notes

Status: release candidate for the public npm Registry on 2026-08-28.

## Highlights

- Adds `all` and `primary` module scopes. New installations default to `all`,
  so every detected Android module's `src/main`, `src/test`, and
  `src/androidTest` trees can participate without selecting a primary module.
- Keeps upgrades from configurations without `androidProject.moduleScope` in
  `primary` mode unless the operator explicitly passes `--module-scope all`,
  preventing a silent expansion of editable paths.
- Adds `--module-scope <all|primary>` and configurable Gradle verification task
  matrices to both `init` and `upgrade`.
- Binds focused-test contract entries to an allowed Gradle task and test filter,
  and strengthens contract, scope, RED-evidence, verification-output, and
  integration checks.
- Retries OpenCode configuration discovery only for the known transient SQLite
  checkpoint failure.

## Compatibility and verification

- The plugin remains restricted to APIs shared by certified OpenCode versions
  `1.14.22` and `1.15.13`; the peer range remains
  `>=1.14.22 <1.16.0`.
- TypeScript type checking, 124 Node tests, the audited 38-case Shell lifecycle
  suite, deterministic packing, and clean-consumer checks gate publication.
- Agent permissions remain unchanged: Coder can edit Android production/test
  source sets selected by the task contract, while Gradle configuration,
  OpenCode configuration, automation resources, and control state stay
  protected.

## Upgrade from 0.2.0

Run the fixed `0.3.0` doctor before upgrading:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.3.0 doctor . --json
npx @frankzhang2026/opencode-android-orchestrator@0.3.0 upgrade . --json
```

Published `0.2.0` configurations do not contain `moduleScope`, so the upgrade
preserves their effective single-module behavior as `primary`. To adopt the new
all-module scope during the version upgrade, add `--module-scope all` and review
the regenerated task example before approving automation.

## Security and recovery

The package still exposes only the read-only
`android_orchestrator_status` and `android_orchestrator_doctor` custom tools.
It does not push Git changes, register background jobs, or bundle Superpowers.
Read [`docs/SECURITY.md`](../docs/SECURITY.md) before enabling model-driven
execution and [`docs/TROUBLESHOOTING.md`](../docs/TROUBLESHOOTING.md) before
manual recovery.

The exact published artifact checksum and Registry round-trip evidence will be
recorded in `release/0.3.0-authorization.md`. npm publication does not imply a
Git tag or GitHub release.
