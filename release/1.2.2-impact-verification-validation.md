# Impact-scoped verification and environment recovery validation

Date: 2026-10-11. Source baseline:

This is an unpublished development change. Package metadata remains 1.2.2;
the local validation tarball is not the immutable Registry release.

## Behavior

New contracts generated from discovered Gradle capabilities explicitly approve
affected Debug verification (or all variants when no Debug variant exists).
The complete capability matrix remains an allowlist. Baseline tests cover the
approved path envelope; GREEN, independent Review and integration select from
actual changes, including deletions and both sides of renames. Production
changes include transitive consumers. Test-only edits do not require unrelated
application assembly. Explicit target tests and acceptance tasks remain required.
Unknown source mappings and Release-only changes under Debug approval fail
closed. Existing approved contracts retain their previous verification behavior.

Focused tests, affected unit suites, assembly, lint, device tests and inventory
validation have separate evidence. Identified dependency transport failures
retry only the failed step under the approved environment budget. Certificate,
authorization, missing-artifact, compilation and assertion failures are not
automatically retried as transient network errors. Environment exhaustion does
not consume implementation repair attempts.

Recovery binds the candidate, contract, configuration, actual Gradle/JVM,
environment inputs and immutable evidence to the queue checkpoint ledger.
Approved resume-task can continue an environment-blocked GREEN or Review
candidate; Review still obtains a fresh Reviewer decision. Integration recover
continues the same committed candidate. Manual and automatic budgets remain
bounded. Paused queues permit approved abort maintenance while retaining
workspace and process ownership checks.

## Evidence and limits

Evidence is under `taskdescriptions/orchestrator-impact-verification/validation/`
in the cctest development workspace. Queue integration tests execute real Git,
queue, Worker, approval and recovery code with simulated Gradle/OpenCode
responses. The separate Android fixture executes actual Gradle/AGP tasks.

not a contract migration or a live WordPress build. The preview retains explicit
acceptance tasks, including assembleDebug, when declared by that contract.

This work does not publish npm, push Git changes or upgrade WordPress.
