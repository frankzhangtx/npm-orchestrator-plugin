# OpenCode Android Orchestrator 0.5.0 Release Notes

Status: release candidate for the public npm Registry on 2026-08-31.

## Highlights

- Makes plain `init .` discover registered Android debug verification tasks
  through one temporary, read-only Gradle init script. Standard task names are
  collapsed to portable selectors while flavor-specific unit and connected
  device tasks retain exact module paths.
- Removes the need for a project-specific Gradle verification JSON file in the
  normal flow. `--gradle-verification-config` remains an explicit override for
  intentionally nonstandard project policy.
- Treats root-project plugin declarations using either `apply false` or
  `.apply(false)` as declarations rather than applied Android modules, avoiding
  false root-module selection.
- Creates a comment-only `.automation-worktree-allowlist` during successful
  `init` when the file is missing, preserves an existing regular file, and
  removes a newly created file if installation verification rolls back.
- Keeps the human-owned allowlist outside the 45 managed-resource hashes so
  operator edits do not create installation-integrity drift; upgrade and
  uninstall preserve it.

## Compatibility and verification

- The plugin remains restricted to APIs shared by certified OpenCode versions
  `1.14.22` and `1.15.13`; the peer range remains
  `>=1.14.22 <1.16.0`.
- TypeScript type checking, 134 Node tests, the audited 42-case Shell lifecycle
  suite, deterministic packing, and clean-consumer checks gate publication.
- Gradle discovery is configuration-only but still executes the target
  project's normal Gradle configuration and dependency resolution. Discovery
  failure stops before installation writes.

## Install and upgrade

After publication, initialize a new project with the fixed version:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.5.0 init . --json
```

For a healthy manifest-managed installation, run the target version's doctor
before upgrading:

```sh
npx @frankzhang2026/opencode-android-orchestrator@0.5.0 doctor . --json
npx @frankzhang2026/opencode-android-orchestrator@0.5.0 upgrade . --json
```

New `init` installations discover their verification matrix automatically.
Upgrade preserves the installed matrix unless an explicit reviewed
`--gradle-verification-config` is supplied, so inspect older project policy
before migrating a flavored application.

## Security and release state

The package still exposes only the read-only
`android_orchestrator_status` and `android_orchestrator_doctor` custom tools.
It does not push project Git changes, register background jobs, or bundle
Superpowers. Read [`docs/SECURITY.md`](../docs/SECURITY.md) before enabling
model-driven execution and
[`docs/TROUBLESHOOTING.md`](../docs/TROUBLESHOOTING.md) before manual recovery.

Preparing and pushing this release candidate does not publish the npm package,
create a Git tag, or create a GitHub Release. Registry checksums and publication
evidence must be recorded separately if npm publication is explicitly
authorized later.
